<Вводные>
Есть файл regions.yml с регионами для плагина WorldGuard для Minecraft. 
В нем содержатся регионы типа Cuboid, которые представляют собой простой куб, обозначенный двумя противоположными вершинами.
Также есть регионы типа poly2d. Это полигональные регионы, у которых есть минимальная и максимальная высота и точки, которые обозначают границы.

В файле all_flags.txt содержатся все доступные флаги регионов. 
там все скопировано с интернета, поэтому не очень удобный формат.
</Вводные>


<Задача>
Написать программу, которая визуально строит иерархическое дерево всех регионов на карте.
</Задача>


<Функционал>
1) Можно выбрать файл, из которого будем загружать регионы.
2) После построения схемы можно её сохранить также в файл, чтобы не перестраивать заново. Файл должен открываться на просмотр после закрытия программы.
3) Нужно просчитать пересечение каждого региона с каждым и отобразить все пересечения и полные вхождения одного региона в другой на схеме между каждым регионом.
4) возможность добавлять новые элементы на схему, указывать родителя, все параметры, которые есть у региона, включая флаги.
5) при добавлении нового региона не нужно вбивать координаты, это я буду использовать, когда буду добавлять регионы в minecraft, чтобы я не забыл, что уже добавил. Затем я все равно отдам программе новый сгенерированный плагином файл, который попрошу отрисовать. Так что добавление региона на схему это временно, просто чтобы он там был пока я нахожусь в процессе программирования регионов.
6) предусмотреть вывод следующих метрик по отдельной кнопке, на общую схему этим не мусорить:
6.1) Количество регионов
6.2) Отсортированные списки:
6.2.1) по убыванию по объему блоков, занимаемым регионом
6.2.2) по убыванию по количеству точек в регионе (только для регионов poly2d)
6.2.3) по убыванию по количеству пересечений региона с другими.
7) покрыть юнит тестами, чтобы ты при разработке мог тестировать и меньше ловить ошибок.
</Функционал>

<Визуальная_составляющая>
1) Схема должна быть прокручиваемой и масштабируемой чтобы можно было передвигаться по ней перетаскиванием мыши во все 4 стороны и приближать её и отдалять.
2) Каждый следующий уровень вложенности должен обозначаться уникальным цветом, который сильно отличается от родительской группы. Если группы далеко, цвета могут быть похожими, главное, чтобы родитель и сын были разных цветов и это легко читалось.
3) глобальные регионы, у которых нет никаких точек в пространстве должны по визуальному оформлению отличаться от обычных регионов.
4) все регионы должны рисоваться в виде кружков, или овалов, в то время как глобальные регионы должны рисоваться, например, в виде облака, или какой-то другой уникальной фигуры.
5) для удобства, возможно будет лучше, если каждый следующий уровень вложенности регионов будет поменьше масштабом (и чтобы эту разницу можно было задать перед рендерингом схемы или при просмотре схемы, чтобы можно было изменять. Моментальный отклик не нужен. Я понимаю, что отрисовка занимает время. На составление сам файл схемы это не должно влиять, это просто как параметр отображения.)
5) Я должен иметь возможность скопировать название любого региона на схеме.
6) В элементе схемы должно быть название региона и его приоритет и уровень его вложенности. У корневого элемента дерева уровень вложенности 0.
7) по клику на регион должны открываться его флаги, приоритет и все параметры, которые у него есть. Флаги можно спрятать в отдельную кнопку, которая будет во всплывающем окне с данными этого региона, чтобы не мешалось. Флаги отображать в каком-то удобном виде, например, в виде таблицы. Если флагов слишком много то во всплывающем окне должен быть скроллинг.
8) возможность "свернуть" и "развернуть" детей региона. То есть скрывать "по минусу" и "по плюсу" отображать детей заново.
9) если дети региона свёрнуты, то все пересечения его детей перенаправить на этот родительский регион.
10) добавить кнопку "свернуть рекурсивно" и "развернуть рекурсивно" для регионов.
</Визуальная_составляющая>

7) Этот файл не изменять и прописать запрет на его изменение для себя.
